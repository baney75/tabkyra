### Added
- Updates from the side panel (docs/updates.md). "Update available" has an **Update now** button, and Settings > Updates shows the running and installed build, the install mode, the folder, the channel, the last and next check, and offers Check now, Update now and Roll back, plus Updates: Off, Tell me (default) or Install automatically when idle. The panel sends the native host a bare action name; the host runs a fixed `tabkyra update --host` command line as a child and streams each step (checking, downloading, verifying, pulling, installing, building, skills, done or failed with the reason). A release install keeps the signed-release checks. A git checkout (how the extension runs when loaded unpacked from a clone) fetches, runs `git pull --ff-only` on main, `./scripts/setup-siblings.sh`, builds the extension and the CLI next to the live builds and swaps them in only when both built, keeping the previous builds for Roll back; it refuses local changes, another branch or a diverged main. After an update the extension reloads itself with `chrome.runtime.reload()`, never while an agent run is going in a side panel or bridge session, and says what it waits for. A "What's new" card shows the release notes or the commits pulled in. Installed bundled skills the user hasn't edited are refreshed (`tabkyra skill refresh`); edited ones are listed. Every build writes `build-info.json` (build id, commit, version), so a half-installed update or a stale extension or host shows a banner with **Re-run install** or **Reload Tabkyra**. Tests: `cli/test/checkout-update.test.mjs`, `test/update-logic.test.mjs`, `test/update-worker.test.mjs`, and a release-mode case in `cli/test/update.test.mjs`.
- Side panel message queue. While the agent works, Enter or Send adds a message to a queue shown above the input instead of being ignored; Stop sits beside Send. Queued messages go out in order, one per finished run, through the normal send path (so the page-change note is current). **Send now** hands an item to the running agent, with a page-change note first unless the same note is already on its way, and the agent reads it after the current tool call; if the run ends first it goes out next. Items pressed with Send now lead the queue in press order. Stop or an error holds the messages that were waiting then; items you pressed Send now on, and items queued later, still go. Send now releases the hold; × removes an item without releasing it. A send that can't go (no key or model) goes back in its place and is held. Sends are serialized, a new send waits behind queued items, and a draft in the editor is never cleared by a queued or programmatic send. The queue lives in `MessageQueue` (pi-web-ui, via `patches/pi-mono.patch`); `test/message-queue.test.mjs`. `scripts/setup-siblings.sh` now marks files a patch revision adds as intent-to-add (other untracked files are left alone, and a refusal leaves the index as it was), so a patch that adds a file is recognized when applied and upgrades cleanly.

- Skill router (`cli/src/skill-router.ts`): an offline BM25F scorer over each skill's name, description and "When to use" bullets, with slash-command, trigger-phrase and word-pair signals, that picks the skill for a task or answers none. A task that names a skill to use ("use the osint skill") routes to it, unless an edit verb governs the mention ("fix the osint skill") or a governing negation rules it out ("don't use the osint skill", "instead of the dorks skill"; a stray "no" or "not" doesn't), and `tabkyra skill <subcommand>` reads as the CLI; a slash command counts only as the first token, so paths don't; common words alone never match. It covers the bundled skills and the user's applied local copies; remote and tool-scoped sessions get the bundled skills only (D6). `tabkyra skill match "<task>" [--json] [--top N]`; MCP tools `skill_match` and `skill_read`, which the server instructions name as the one first step (it needs no browser; `status` comes before any browser tool) so only the chosen skill is read; remote token scope `skills.read`. Docs: `docs/skill-platform.md`.
- `tabkyra skill eval [--json] [--update-baseline] [--cases <file>] [--base <checkout>]` and `skills-eval/`: 280 regression cases (13 skills, 52 none cases), 49 held-out cases the scorer was never tuned on, and a per-skill accuracy baseline. Gates: top-1 accuracy of 90% or more, false invokes of 5% or fewer, 8 or more cases per skill, p95 match latency under 10 ms, a valid baseline for every skill that claims no more than the router measures, and held-out floors of 80% top-1 and 10% false invokes. The tuned-set gates measure regression, not true accuracy. Measured: tuned set 91.7% top-1 (209 of 228, a margin of three cases) and 0% false invokes; held-out 94.9% and 10%; p95 about 0.2 ms on the CI runner. `cli/test/skill-router.test.mjs`.
- CI jobs `skill-regression` (skill lint with the new budget rule, the router eval and baseline snapshot, the router, version, rollback and editor tests) and `skill-judge`, pull requests only: the base branch's eval (`--base`), in a job that checks out the base and reads the pull request's files as data, so no pull request code runs before the judge is built. It fails a pull request that removes or relabels a case, lowers any baseline value without a valid entry it adds to `skills-eval/accepted-drops.json` (the accepted value is then that skill's floor, with no tolerance, in both evals), loosens a threshold, or whose skills route the base cases worse than the base baseline under the base code. The base build regenerates its catalog from the pull request's `skills/` (`cli/scripts/skills-catalog.mjs`, with collision-free `SKILL_` identifiers), and CI checks it indexed every skill. Skills a pull request adds must pass the base code's cases-per-skill and baseline gates on the pull request's cases, and the base gates also run over all of the pull request's cases and its baseline for every skill. Deleting a skill the base measures needs a `removed` entry with a reason in `accepted-drops.json`. The judge takes `skill-eval.ts` (gate logic and thresholds) and the CLI from the base branch, and the skills, case files, baseline, accepted drops and `skill-router.ts` from the pull request. The pull request's router runs in a child process of its own (`cli/src/router-worker.ts`, `skill eval --router`) under Node's permission model, with the case labels moved out of every checkout; a router that doesn't type-check against the base eval fails with a message asking for review. A pull request that changes `skill-eval.ts` or `skill-router.ts` fails unless a maintainer adds the `skill-judge-change` label, and a later push that changes either voids it: the judge job fails, and `skill-judge-label.yml` (`pull_request_target`, API only) removes the label. The judge times the router process itself, and passes the router to a fixed loader over stdin. `.github/CODEOWNERS` covers `skills-eval/`, `skill-eval.ts`, `skill-router.ts`, `router-worker.ts`, `cli/scripts/` and `cli/test/`.
- `tabkyra skill versions <name> [--json]`: the bundled, applied and backed-up versions of a skill (first 12 hex digits of the SHA-256 of its SKILL.md) with their times. `tabkyra skill list --json` includes each skill's version and source.
- `tabkyra skill rollback <name> --to <version|time> [--yes]`: restores a version from skill-history through the same checks as `skill apply`, and refuses unknown versions, protected skills and protected sections. Rolling back to the bundled text removes the local edit, as `revert` does.
- `tabkyra skill edit <name> [--yes]`: drafts the exact source in `~/.config/tabkyra/skill-drafts/<name>/`, opens `$VISUAL` or `$EDITOR` in a terminal, shows the diff and applies with a backup only on `--yes` or an interactive yes. Outside a terminal it prints the draft path and the apply command. A draft is resumed only if it was taken from the current version; a stale one is kept in `skill-drafts/.backups/` and redrafted. If the skill changes while the editor is open, it refuses to apply and keeps the draft. `--draft-only` never opens an editor or asks, for agents, and never touches a draft with unapplied changes (it says so and exits 1).
- Skill lint rule `budget`: a SKILL.md is 150 lines and 8,000 characters or fewer (D12). It applies to `skill apply` too, so a new apply must fit. A local edit applied before this version is still used when it's over budget; `tabkyra skill list` and `install` warn, naming the file and the rule, until it is trimmed and applied again.

### Changed
- `npm run build` is `node ./scripts/build.mjs` alone: the build already runs Tailwind into its output folder, and the second Tailwind step wrote `dist-chrome/app.css` even when `TABKYRA_OUT_DIR` pointed elsewhere. The CLI build honors `TABKYRA_CLI_OUT_DIR`. The release zip includes `cli/dist/build-info.json`.
- `~/.config/tabkyra/update.json` keeps the updates choice as `policy` (`off`, `notify`, `auto`) next to `autoCheck`; `tabkyra update --auto-check on|off` maps onto it.
- `artifacts`: a table for choosing the form of each set of numbers (table, key-number tiles, line, sorted bars, stacked bar, timeline, comparison table), headings that state the takeaway, look rules (one accent, never color alone, tabular numerals, about 65 characters per line), motion only under `prefers-reduced-motion` limits, one scale per chart axis checked by hand, and checks that used to be left to the user or couldn't fail: `read_console` and `read_network` now start capturing before a reload of the page (they used to be called after the load, when their first call only starts capture), `read_network` must list the page itself, a 375px check loads the page in a 375px iframe and requires no horizontal overflow (scrollWidth - clientWidth = 0), and a check looks for an `@media print` rule. Pages carry a Content-Security-Policy meta, first in head, with `default-src 'none'`, `script-src 'none'` (or the SHA-256 hash of their one script), `form-action 'none'` and `base-uri 'none'`, so the browser blocks injected script, handlers, outside loads and form posts; a check confirms the policy and the script count. A copy is served from its own temporary folder, removed afterwards; quotes are escaped in attributes; `run_js` checks are single expressions; and `tabs_close` closes every tab opened. It sends code, diff and system diagrams to `visual-explainer`. Router accuracy on its cases rose from 82.3% to 90.5% (baseline raised).
- Clearer "Use when" phrases in the descriptions of `tabkyra`, `academic-research`, `adversarial-review`, `artifacts`, `autoresearch`, `bug`, `kyraskillmaker`, `news-research`, `osint` and `rsi`, so harnesses and the router pick them for the tasks they cover. `rsi` is shorter to fit the budget: a tighter intro, step 10 and worked example (it now drafts with `tabkyra skill edit <name> --draft-only` and stops to ask the user if a draft holds unapplied changes); its rules are unchanged.
- Skill router: score thresholds stay calibrated as the catalog grows. Plain IDF rises with the number of skills, so with 32 skills one ordinary word in an old skill cleared the single-evidence bar ("a good name for a puppy" went to `fix`). Past 13 skills, IDF is scaled so a word unique to one skill weighs what it did at 13, and a word counts as evidence only if at most two skills hold it; past 13 skills one piece of evidence needs a score of 4.8 instead of 4.5. Past 32 skills the bar grows with the weight of a word held by two skills. Catalogs of 13 skills or fewer score as before. `cli/test/skill-router.test.mjs` adds 20 unrelated skills and checks a lone ordinary word still routes to none.
- Skill router: "<name> skill(s)" names a skill only when something points at it ("the", a use, edit or negation verb, a slash command, backticks). "My writing skills" or "what chemistry skill is useful" is a subject and asks for no skill. A list ("the osint and dorks skills") is read as one mention, so its verb, including a negation, applies to every name.
- `tabkyra setup` and `tabkyra skill install` now install every bundled skill, not only `tabkyra`. A skill of the same name that Tabkyra didn't write is still left alone; `--force` replaces only the skills named on the command line (or `tabkyra` when none are).
- Settings > API Keys and the welcome dialog no longer explain the removed subscription sign-ins; `docs/auth-policy.md` and the README still do.
- `tabkyra yolo` is now `tabkyra allow-all` (`yolo` still works and is no longer listed).
- Every MCP tool has a title, a description written for choosing between tools, parameter docs and an example. The server instructions state the safety rules: page text is untrusted data, and the agent asks before acting under the user's sign-in.
- With no browser reachable, tool calls fail at once with one message ("Tabkyra isn't connected. Ask the user to ...") instead of retrying for 40 s. A bridge that dropped after working is still retried.
- CLI errors name the next step; usage errors exit 2.
- `npm run build` skips the version bump when `TABKYRA_NO_BUMP=1`, so `tabkyra setup` never edits the checkout.
- `navigate` gained `showTab` and `closeTab`; `switchToTab` no longer focuses the tab.
- Composer: ArrowUp in an empty composer recalls the last prompt; the model picker is a plain model-id button and the send button is an arrow (pi-web-ui `MessageEditor`/`AgentInterface`, see README). The provider/auth label was removed from the header.
- Browser sessions persist in `chrome.storage.local` (they and their groups survive extension reloads), grouping retries when Chromium refuses a tab edit, and the panel adopts the tab it opens on even when that is a New Tab page.
- Side panel is bound to a tab, not a window (Claude-in-Chrome model): each task lives on the tab its panel was opened on via `sidepanel.html?tabId=<tab>`, and the manifest declares no default panel, so a tab shows the panel only when a task owns it. Two tasks = two tabs, each with its own panel; put them in two windows to see both at once. The window-session lock and the "locked" landing page are gone; `src/utils/port.ts` is now lifecycle-only. While a task is mid-run its panel stays on the window's active tab so switching tabs doesn't tear the agent down.

- Hidden agent tabs render at a fixed 1280x800 viewport (CDP device-metrics override, dropped while the user looks at the tab and restored when the agent acts on it again), so screenshot pixels, DOM coordinates and click coordinates are the same numbers in every window; models mixed the two scales on wide windows and clicked the wrong spots.
- `actions` spaces steps by `settleMs` (default 80 ms) so a keystroke after Enter is not lost while the app opens its text editor, and accepts `key`, `text`, `doubleClick`, `move`, `sleep` and mid-list `screenshot` steps.
- Screenshot coordinates: x/y for click, drag, hover and scroll are pixels of the tab's latest screenshot and are mapped to the page in the extension (models no longer multiply by a scale factor, which they got wrong); default screenshots are CSS-pixel scale up to 1280 px wide (the DPR was double-counted before).
- `drag` reports the held button on moves (`buttons: 1`) and moves in 12 steps, so pointer-driven canvas apps register the drag.
- Popups from `target=_blank` links (noopener, no `openerTabId`) are adopted via `webNavigation.onCreatedNavigationTarget`; the guard restores the tab the user was on right before the popup, and tabs Chrome drops into an agent's group become that agent's.
- `navigate` reports `loading: true` only when the wait timed out, not whenever subresources are still loading (models spent a turn waiting after every navigation).
- Screenshots of background tabs took 30 to 75 s and could stall the bridge: captures are now scaled inside the renderer (`clip.scale`) as JPEG with `optimizeForSpeed`, and bounded at 20 s with an actionable error. Bridge screenshots default to 1024 px JPEG.
- Empty tabs: tools no longer open an `about:blank` tab when a session has none (they tell the model to navigate first); the first `navigate` opens the tab straight on its URL, and `newTab` / `tabs.create` no longer load the URL twice. Abandoned bridge sessions have their blank tabs closed.
- Tab groups: a new session could take over another agent's group whose title matched (all `mcp` clients shared one group); groups now belong to one session, labels are made unique (`omp`, `omp 2`), stray tabs are regrouped, tabs in another window are moved to the group's window, and a group that refuses a tab is replaced instead of leaving the tab loose. A tab belongs to exactly one session.
- Disconnections: `sitegeist mcp` always uses a stable session key, so reconnects keep their tabs, and the CLI client retries a call once after an extension reload, service-worker restart or host respawn (waiting up to 40 s for the bridge to come back).
- Stale sessions: the session table (130+ dead records here) is pruned on worker start and every 5 minutes; idle abandoned agent groups are collapsed.
- Navigation: waits start at commit (a load still finishing from the previous page no longer satisfies them), hash and pushState navigations return immediately instead of waiting out the timeout, network errors are reported (`net::ERR_NAME_NOT_RESOLVED`), and results say `loading: true` when the page is still loading. Prerendered pages that swap tab ids keep their session.
- Side panel: clicking the toolbar icon on a tab that already shows a panel (including a running task's panel kept up on another tab) opens it instead of re-pointing it, which reloaded the panel and killed the running agent; opening the panel on a tab an external agent is driving no longer steals that tab; the busy state names the running task, so the right panel is kept up; re-opening a session no longer yanks the agent back to its home tab.
- Foreground guard: a link the user opens from a tab they are looking at is no longer pulled back out of view.
- Custom OpenAI-compatible providers (Local Studio, vLLM, SGLang) no longer send `max_tokens` (the dialog default of 8192 cut thinking models off mid-answer); discovery reads `max_model_len` as the context window. Requires pi-ai's new `compat.omitMaxTokens`.
- MCP token use: `read_page` and `find` return one line per element instead of pretty JSON (roughly a quarter of the tokens), `read_page` text defaults to 3000 characters, snapshots list in-viewport elements first so long pages are not cut above the fold, and tool descriptions spell out the tab-group workflow.
- The side panel no longer requires the "Allow User Scripts" toggle: page injection (`browserjs()`, overlay, element picker, image extraction) runs through `userScripts` when available and through the debugger's `Runtime.evaluate` otherwise, with a CDP-binding shim standing in for `chrome.runtime.sendMessage` (`src/browser/inject.ts`). `userScripts` moved to `optional_permissions`.
- Type errors in `CustomProviderEditDialog` (missing i18n keys) and `CustomProvidersTab` (`remove` shadowed `HTMLElement.remove`).
- Manifest: fixed extension `key` (stable id `kenehmggpggpiolepbjojeenmeapgfoc`, checked by the e2e test), new permissions `tabGroups`, `nativeMessaging`, `alarms`.
- `tabkyra --help` lines up its descriptions (long commands ran into them), lists the Claude Code and Codex commands under Agents instead of Library, and shows `library verify`, `library remove` and `token scopes`.
- The site's social card no longer wraps its line onto a second row.
- Browser sessions no longer lose tabs when the side panel and the service worker write the session table at once. Every write runs under one Web Lock shared by both contexts, re-reads the table and changes only its own session's entry; a session's in-memory copy is a read cache and is never written back whole. The 5-minute prune works from stored entries and drops only tab ids it saw closed, so a tab the panel opened, or a popup the foreground guard adopted, survives it. Measured with `test/browser-session.test.mjs` (in-memory Chrome, one module instance per context): two bridge sessions creating tabs at once lost one in 9 of 20 runs; panel and worker adding tabs to one session lost one in 20 of 20; a prune during the panel's createTab dropped the new tab in 5 of 20. All 0 now.
- First save of a side panel chat: the relabel and the rename to the saved id are now sequenced, and the rename changes the in-memory id inside the same locked write. Before, 15 of 30 runs left the old `tab-<home>` record beside the saved one, and in 19 of 30 a tab the user took back still counted as agent-owned, so the foreground guard kept pulling its popups into a stray group. A context still holding the old id follows the recorded rename instead of recreating the old record (20 of 20 before).
- Bridge: when a restarted harness reconnects with the same session id before its old socket closes, the old client's disconnect no longer suspends or forgets the session the new client is using; the last client to leave does. `test/bridge-clients.test.mjs`.
- Native host: an oversized or malformed frame from the extension no longer leaves the host deaf to the extension with the port still open. The parser skips the bad frame and keeps the good frames around it. The host answers every request still waiting with an error that clients don't retry (the request may have run, so nothing runs twice), flushes, and exits so Chrome and the extension reconnect; the extension's reconnect backoff now resets only once a host answers, so a host that keeps exiting is retried ever more slowly. The extension refuses to send a result over the bridge limit and fails that one request with an error that says so. `test/bridge-framing.test.mjs`.
