# Changelog

## [Unreleased]

### Added
- Agents see what's inside web components and frames. `read_page` and `get_page_text` now include open shadow roots and same-origin frames, refs inside them work with click, type and fill (a frame's offset is added for clicks; `fill` works across frame realms), and a frame from another site is listed as `iframe` with its URL. Each element also shows its state: expanded or collapsed, pressed, selected, checked, current, disabled, required, invalid. `cli/eval/perception.mjs` measures it: 4 of 20 probes pass on main, 20 of 20 with this change (docs/benchmarks.md, which also scores each reviewed head).
- Agents can read the data a page loads. `read_network` lists each request's id and type (filter with `type`, e.g. `Fetch`), with credential-named query parameters masked in every URL. `read_network {"requestId":...}` shows two things, for same-origin requests only: what the request sent, as its shape (keys and value types, never a value; it carries what the user typed), and the response when it is complete JSON. In the response, values under credential-named keys (password, token, secret, key, session, CSRF, cookie, one-time code, card number, ...) become `[secret]`, edited in place so ids and every other byte come back as sent. A string that holds a credential as text is masked whole. Other responses (HTML, text, bodies over 2 MB) aren't shown: `get_page_html` and `run_js` cover them. A read-only remote session (`browser.read`) can list requests but not read details: that needs `browser.script`.
- `inspect_page` maps how a page is built: framework, embedded JSON (names and top-level keys), forms (field names, never values), frames, web components, script hosts, storage and cookie names (never values) and the API calls `read_network` saw. tools/list grows by 593 bytes (budget 27,400).
- The `tabkyra` skill says when `read_page` isn't enough: frames from other sites, a page's own JSON through `read_network`, `inspect_page`, and `run_js` to read, never to act or to read cookies.
- Dictation: press the composer's microphone and speak; it turns to text on your computer, not a server (D29). The model fits the device: Whisper large-v3 turbo on a GPU with half precision and 8 GB or more, Whisper small on another GPU, Moonshine base (English) or Whisper base on the processor, the tiny models under 4 GB. It downloads once from Hugging Face, pinned to a commit; a download of 200 MB or more is asked for first. Settings > Privacy > Dictation shows the model and why, picks another model or a language, and removes the download. Silence is trimmed and a silent recording sends nothing; Esc cancels; recording stops at 5 minutes. The speech runtime (onnxruntime-web) ships inside the extension, and the CSP gains `'wasm-unsafe-eval'`. The microphone permission is granted once in a Tabkyra tab, since a side panel can't ask. pi-web-ui gains a `composerActions` slot through `patches/pi-mono.patch`. Measured by `cli/eval/dictation.mjs` (`docs/benchmarks.md`); tests in `test/dictation.test.mjs`.
- Community skills (D27, [CONTRIBUTING-skills.md](CONTRIBUTING-skills.md)). Agents manage skills without editing files: `tabkyra skill write` (lint on every write, `--yes` saves), `skill test` (lint, community rules and the router eval CI runs), `skill remove` and `skill enable`, and one MCP tool, `skill_manage` (list, write, test, remove, prepare_submit; local stdio server only). `skill list` and `skill_manage` list show each skill's provenance: built-in, community with its catalog, or local. `tabkyra skill submit` proposes a skill to `community/` as a fork pull request through the user's `gh`: it refuses without `gh` signed in (one-line fix) and with any personal data, runs the checks CI runs, shows the exact preview and sends only with that preview's `--confirm` code; its MCP action `prepare_submit` only prepares. CI lints community skills with the community rules (scope to their sites, no page scripts, credential requests, exfiltration or personal data), routes them as clients do in the regression eval and the judge, and keeps community pull requests inside `community/`. Merged skills ship in a catalog signed with the release key in CI (`.github/workflows/community-catalog.yml`) and synced about daily by the native host, `tabkyra mcp` and `tabkyra skill sync`; unsigned, tampered, mis-signed and older catalogs are refused, local edits are kept, and pulled skills are removed. Settings > Skills turns them off. Tests: `cli/test/community.test.mjs`.
- Free mode (D26): the side panel runs on the best free OpenRouter model. "Free (best available)" leads the model selector, and Settings > Providers has a Free mode switch. The ranking is measured by `cli/eval/free-models.mjs` (four fixture tasks through Tabkyra's MCP tools in a headless Chromium, scored by the site's state) and merged by `cli/eval/free-ranking.mjs` into `src/models/free-ranking.json`. At run time the free list is reread daily and filtered to `:free` models with every price zero and `tools` support. Each request sends OpenRouter's `models` fallback list (two best free models, then `openrouter/free`), every id checked free, with `provider.max_price` zero; a fully limited list moves on to the next models once, then ends with the free daily limit. Private mode keeps only free zero-data-retention models and refuses when there are none. Without an OpenRouter key the key prompt explains how to get a free one. The model button reads "Free · <model>": pi-ai records the model a router reports (`responseModel`) and pi-web-ui gains `setPinnedModels` (the label uses the composer's `modelLabel`), through `patches/pi-mono.patch`. `cli/eval/free-mode-turn.mjs` runs one real side panel turn in Free mode. `test/free-mode.test.mjs`. The eval fixture site moved to `cli/eval/fixture-site.mjs`, shared with `skill-eval.mjs`.
- Use your ChatGPT or GitHub Copilot plan in the side panel (D28). Settings > Providers has "Continue with ChatGPT" (OpenAI's Sign in with ChatGPT for open-source apps: dynamic registration, no client secret, a stable host id, a loopback callback on 127.0.0.1, ID token checked against OpenAI's keys, `store: false` streaming requests) and "Sign in with GitHub Copilot" (Tabkyra's own GitHub OAuth App by device flow, inference through GitHub's Copilot SDK, which `tabkyra copilot-sdk install` adds). Tokens stay in the native host in 0600 files under `~/.config/tabkyra/subscriptions`, never in the browser; the side panel reaches the providers through the host's loopback proxy. Sign-out revokes the ChatGPT session and deletes the tokens. Claude and Gemini get no sign-in, since their terms forbid one; Settings shows how to run Claude Code or Gemini CLI with Tabkyra's MCP server instead. Sources in `docs/auth-policy.md`; tests in `test/subscriptions-host.test.mjs`, `test/subscriptions-extension.test.mjs` and `test/auth-policy.test.mjs`.
- Past side panel chats ("threads") for local agents (D24). MCP tools `threads_list`, `thread_search` and `thread_read` (compact text, 40 messages a page), `tabkyra threads list|show|search|export [--json]`, and a mirror the native host writes to `~/.local/share/tabkyra/threads` (`<id>.md`, `<id>.json`, `index.json`; folder 0700, files 0600, atomic writes) a couple of seconds after a chat changes. The service worker reads the panel's IndexedDB directly, so threads are served without an open panel; the CLI and MCP fall back to the files when the browser is closed. Private-mode chats are never served or mirrored; pasted keys are redacted; attachments appear by name. Settings > Privacy turns the mirror off and deletes it. Remote sessions need the new `threads.read` token scope. Tests: `test/threads.test.mjs`, `cli/test/threads.test.mjs`, and a live check in `cli/test/e2e-bridge.test.mjs`.
- `ask_user`: agents can ask you questions. The side panel's agent, and external agents through `tabkyra mcp` and `tabkyra serve`, ask 1 to 4 multiple-choice questions (a short header, the question, 2 to 4 options with a description, and multiSelect); you pick options or type your own "Other" answer, and the answer returns as the tool result, mapped question to answer. Skip, Stop, closing or reloading the panel, a 5-minute timeout (bridge) or the agent disconnecting returns a no-answer result that tells the agent not to assume one. The side panel agent's card is inline in the chat and stays readable in history; an external agent's question shows above the chat in every open panel, names the agent, and badges the toolbar icon while no panel is open. Answers go back only to the agent that asked, through the service worker, and no bridge method can answer a question. Question text renders as text, never HTML. Remote tokens need the new `user.ask` scope. The system prompt, the MCP instructions and the `tabkyra` skill say to ask only when the answer changes what the agent does, with the recommended option first. Code in `src/ask/`, `src/tools/ask-user.ts` and `cli/src/ask.ts`; tests in `test/ask-user.test.mjs`, `cli/test/mcp.test.mjs` and `cli/test/remote.test.mjs`. See D20.
- Side panel `/` menu runs skills. It lists the site skills that match the current page first, then the bundled library (`skills/*/SKILL.md`, what `tabkyra skill list` shows, bundled into the extension at build time as `virtual:library-skills`), then site skills for other sites, each with its short description, filtered as you type (name matches before description matches). Arrows move, Enter or Tab inserts `/<name>`, Esc closes. On send the skill's instructions load into the run and the rest of the message is the task. A `/word` that is not a skill stays plain text.
- Side panel `@` menu references tabs. It lists the open tabs in the panel's window (title, favicon, host), this chat's own tabs first; private (incognito) tabs are never listed, browser pages (chrome:// and the like) show as unavailable, and a tab another agent session owns shows as in use. A chosen tab shows as a chip in the composer and on the sent message. On send, referencing a tab is the user's consent: the tab joins the chat's session through the adopt flow without becoming current (the model is told to switch to it with navigate `switchToTab`, so a reference sent mid-run never moves the agent's next action to another page), and the model gets a compact line per tab (id, title, URL, what happened). A tab another session owns (an external agent or another chat) stays with it (#27, #36): the check and the claim happen under one lock (`BrowserSession.adoptIfFree`), and the model and the user are told. Page titles and URLs reach the model as quoted one-line data. References are resolved once and frozen on the message (`tabkyraRefs`), so a reloaded chat sends the same thing. `test/composer.test.mjs`.
- Sessions that follow the project (D23). Without `--session` or `TABKYRA_SESSION`, `tabkyra mcp` uses the project (the git root of its folder), so a restarted harness finds the tabs it left. Two agents in one project at once get separate sessions and groups in distinct colors; `tabkyra mcp --session <name>` shares one on purpose. Group titles name the agent and the project ("Tabkyra · claude · shop").
- MCP tools `session_info` (name, agent, project, group, tabs, times; `label` names the group), `session_end` (hand the tabs to the user or close them, and forget the session) and `tabs_release` (give one tab to the user, out of the group). `tabs_context` is now a short text summary: the session, news such as a tab the user took, then one line per tab.
- The user's gestures on an agent's group are commands: dragging a tab out or ungrouping it hands it to the user and tells the agent; dragging a tab in gives it to the agent; closing the group ends the session and drops its record; a closed window doesn't. An agent whose current tab was taken has none until it picks one. A session holds at most 15 tabs (`tab_limit`).
- `tabkyra sessions [list|show|rename|end|release|focus|collapse|expand] [--json]` and `tabkyra tabs [session] [--json]`, built on new bridge methods (`sessions.*`) that never open a session of their own.
- `tabkyra completion zsh|bash|fish`: completions for every command, subcommand and flag. Help and the completions come from one command table (`cli/src/commands.ts`), so neither can list a command the CLI lacks.
- `tabkyra version [--json]`; `--json` on `token list`, `token scopes` and `library search`. Exit codes are documented in `--help` and `cli/README.md`: 0 success; 1 failed, not connected or nothing found; 2 usage error; `update --check` exits 100 when an update exists; `library add` exits 3 (retracted) and 4 (check unfinished).
- `cli/eval/bridge-metrics.mjs` (tools/list size and real token cost, cold start, calls across forced extension reloads and host kills, three clients at once, thirteen tab group behaviors) and a `sessions` suite in `cli/eval/skill-eval.mjs` (multitab, resume, parallel, handover, reload), on a shared throwaway browser (`cli/eval/fixture-browser.mjs`). Baseline in `docs/benchmarks.md`.

## [1.1.9] - 2026-10-27

### Added
- Updates from the side panel (docs/updates.md). "Update available" has an **Update now** button, and Settings > Updates shows the running and installed build, the install mode, the folder, the channel, the last and next check, and offers Check now, Update now and Roll back, plus Updates: Off, Tell me (default) or Install automatically when idle. The panel sends the native host a bare action name; the host runs a fixed `tabkyra update --host` command line as a child and streams each step (checking, downloading, verifying, pulling, installing, building, skills, done or failed with the reason). A release install keeps the signed-release checks. A git checkout (how the extension runs when loaded unpacked from a clone) fetches, runs `git pull --ff-only` on main, `./scripts/setup-siblings.sh`, builds the extension and the CLI next to the live builds and swaps them in only when both built, keeping the previous builds for Roll back; it refuses local changes, another branch or a diverged main. After an update the extension reloads itself with `chrome.runtime.reload()`, never while an agent run is going in a side panel or bridge session, and says what it waits for. A "What's new" card shows the release notes or the commits pulled in. Installed bundled skills the user hasn't edited are refreshed (`tabkyra skill refresh`); edited ones are listed. Every build writes `build-info.json` (build id, commit, version), so a half-installed update or a stale extension or host shows a banner with **Re-run install** or **Reload Tabkyra**. Tests: `cli/test/checkout-update.test.mjs`, `test/update-logic.test.mjs`, `test/update-worker.test.mjs`, and a release-mode case in `cli/test/update.test.mjs`.
- Side panel message queue. While the agent works, Enter or Send adds a message to a queue shown above the input instead of being ignored; Stop sits beside Send. Queued messages go out in order, one per finished run, through the normal send path (so the page-change note is current). **Send now** hands an item to the running agent, with a page-change note first unless the same note is already on its way, and the agent reads it after the current tool call; if the run ends first it goes out next. Items pressed with Send now lead the queue in press order. Stop or an error holds the messages that were waiting then; items you pressed Send now on, and items queued later, still go. Send now releases the hold; × removes an item without releasing it. A send that can't go (no key or model) goes back in its place and is held. - Screenshots of background tabs took 30 to 75 s and could stall the bridge: captures are now scaled inside the renderer (`clip.scale`) as JPEG with `optimizeForSpeed`, and bounded at 20 s with an actionable error. Bridge screenshots default to 1024 px JPEG.
- Empty tabs: tools no longer open an `about:blank` tab when a session has none (they tell the model to navigate first); the first `navigate` opens the tab straight on its URL, and `newTab` / `tabs.create` no longer load the URL twice. Abandoned bridge sessions have their blank tabs closed.
- Tab groups: a new session could take over another agent's group whose title matched (all `mcp` clients shared one group); groups now belong to one session, labels are made unique (`omp`, `omp 2`), stray tabs are regrouped, tabs in another window are moved to the group's window, and a group that refuses a tab is replaced instead of leaving the tab loose. A tab belongs to exactly one session.
- Disconnections: `sitegeist mcp` always uses a stable session key, so reconnects keep their tabs, and the CLI client retries a call once after an extension reload, service-worker restart or host respawn (waiting up to 40 s for the bridge to come back).
- Stale sessions: the session table (130+ dead records here) is pruned on worker start and every 5 minutes; idle abandoned agent groups are collapsed.
- Navigation: waits start at commit (a load still finishing from the previous page no longer satisfies them), hash and pushState navigations return immediately instead of waiting out the timeout, network errors are reported (`net::ERR_NAME_NOT_RESOLVED`), and results say `loading: true` when the page is still loading. Prerendered pages that swap tab ids keep their session.
- Side panel: clicking the toolbar icon on a tab that already shows a panel (including a running task's panel kept up on another tab) opens it instead of re-pointing it, which reloaded the panel and killed the running agent; opening the panel on a tab an external agent is driving no longer steals that tab; the busy state names the running task, so the right panel is kept up; re-opening a session no longer yanks the agent back to its home tab.
- Foreground guard: a link the user opens from a tab they are looking at is no longer pulled back out of view.
- Custom OpenAI-compatible providers (Local Studio, vLLM, SGLang) no longer send `max_tokens` (the dialog default of 8192 cut thinking models off mid-answer); discovery reads `max_model_len` as the context window. Requires pi-ai's new `compat.omitMaxTokens`.
- MCP token use: `read_page` and `find` return one line per element instead of pretty JSON (roughly a quarter of the tokens), `read_page` text defaults to 3000 characters, snapshots list in-viewport elements first so long pages are not cut above the fold, and tool descriptions spell out the tab-group workflow.
- The side panel no longer requires the "Allow User Scripts" toggle: page injection (`browserjs()`, overlay, element picker, image extraction) runs through `userScripts` when available and through the debugger's `Runtime.evaluate` otherwise, with a CDP-binding shim standing in for `chrome.runtime.sendMessage` (`src/browser/inject.ts`). `userScripts` moved to `optional_permissions`.
- Type errors in `CustomProviderEditDialog` (missing i18n keys) and `CustomProvidersTab` (`remove` shadowed `HTMLElement.remove`).
- Manifest: fixed extension `key` (stable id `kenehmggpggpiolepbjojeenmeapgfoc`, checked by the e2e test), new permissions `tabGroups`, `nativeMessaging`, `alarms`.
- `tabkyra --help` lines up its descriptions (long commands ran into them), lists the Claude Code and Codex commands under Agents instead of Library, and shows `library verify`, `library remove` and `token scopes`.
- The site's social card no longer wraps its line onto a second row.
- Browser sessions no longer lose tabs when the side panel and the service worker write the session table at once. Every write runs under one Web Lock shared by both contexts, re-reads the table and changes only its own session's entry; a session's in-memory copy is a read cache and is never written back whole. The 5-minute prune works from stored entries and drops only tab ids it saw closed, so a tab the panel opened, or a popup the foreground guard adopted, survives it. Measured with `test/browser-session.test.mjs` (in-memory Chrome, one module instance per context): two bridge sessions creating tabs at once lost one in 9 of 20 runs; panel and worker adding tabs to one session lost one in 20 of 20; a prune during the panel's createTab dropped the new tab in 5 of 20. All 0 now.
- First save of a side panel chat: the relabel and the rename to the saved id are now sequenced, and the rename changes the in-memory id inside the same locked write. Before, 15 of 30 runs left the old `tab-<home>` record beside the saved one, and in 19 of 30 a tab the user took back still counted as agent-owned, so the foreground guard kept pulling its popups into a stray group. A context still holding the old id follows the recorded rename instead of recreating the old record (20 of 20 before).
- Bridge: when a restarted harness reconnects with the same session id before its old socket closes, the old client's disconnect no longer suspends or forgets the session the new client is using; the last client to leave does. `test/bridge-clients.test.mjs`.
- Native host: an oversized or malformed frame from the extension no longer leaves the host deaf to the extension with the port still open. The parser skips the bad frame and keeps the good frames around it. The host answers every request still waiting with an error that clients don't retry (the request may have run, so nothing runs twice), flushes, and exits so Chrome and the extension reconnect; the extension's reconnect backoff now resets only once a host answers, so a host that keeps exiting is retried ever more slowly. The extension refuses to send a result over the bridge limit and fails that one request with an error that says so. `test/bridge-framing.test.mjs`.

### Removed

Each posed as another app (Codex CLI, VS Code Copilot Chat, Gemini CLI, Claude Code), which the providers forbid.
